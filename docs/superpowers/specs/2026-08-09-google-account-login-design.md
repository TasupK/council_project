# Google 계정 로그인 설계

## 목표

학생회 통합업무관리 Google Apps Script 웹앱에 Google 계정 기반 로그인 화면을 추가한다. 승인된 사용자만 접근할 수 있으며 비밀번호는 별도로 저장하지 않는다.

## 범위

- 기존 API 설계 스프레드시트는 읽기 전용 참고자료로만 사용한다.
- 운영 데이터용 Google 스프레드시트를 새로 만든다.
- 새 스프레드시트에 `USER` 탭을 만든다.
- 로그인 화면, 사용자 확인 서버 함수, 성공 및 오류 상태를 구현한다.
- 로그인 성공 후에는 사용자 이름과 역할을 보여주는 간단한 환영 화면까지만 제공한다.
- 대시보드와 업무 기능은 이번 범위에 포함하지 않는다.

## 운영 스프레드시트

새 스프레드시트 이름은 `학생회_통합업무관리_DB`로 한다.

`USER` 탭의 열은 다음 순서로 구성한다.

| 열 | 필드 | 설명 |
| --- | --- | --- |
| A | 사용자ID | 사용자 식별값 |
| B | 이메일 | Google 계정 이메일, 로그인 대조 키 |
| C | 이름 | 화면 표시 이름 |
| D | 역할 | 사용자 역할 |
| E | 사용여부 | `Y`인 사용자만 접근 허용 |
| F | 등록일 | 사용자 등록 시각 |
| G | 수정일 | 마지막 수정 시각 |

헤더 아래에는 실제 개인정보 대신 교체 가능한 예시 행 하나만 둔다. Apps Script에는 새 스프레드시트 ID를 설정값으로 저장한다.

## 로그인 흐름

1. 웹앱이 로그인 화면을 표시한다.
2. 사용자가 `Google 계정으로 로그인` 버튼을 누른다.
3. 클라이언트가 Apps Script의 로그인 확인 함수를 호출한다.
4. 서버가 현재 실행 사용자의 Google 계정 이메일을 읽는다.
5. 서버가 `USER` 탭에서 이메일이 일치하고 `사용여부`가 `Y`인 행을 찾는다.
6. 승인된 사용자는 이름, 이메일, 역할을 전달받아 환영 화면으로 이동한다.
7. 이메일을 확인할 수 없거나 미등록 또는 비활성 상태이면 접근 거부 메시지를 표시한다.

## 구성 요소

- `index.html`: 로그인 화면, 처리 중 상태, 오류 안내, 환영 화면과 클라이언트 호출을 담당한다.
- `Code.js`: 웹앱 응답, 현재 사용자 이메일 확인, `USER` 조회, 안전한 응답 생성을 담당한다.
- Google 스프레드시트 `USER` 탭: 승인 사용자와 역할의 운영 기준 데이터다.

## 오류 처리

- 계정 이메일 확인 불가: Google 계정으로 웹앱에 접속하도록 안내한다.
- 미등록 계정: 관리자에게 사용자 등록을 요청하도록 안내한다.
- 비활성 계정: 현재 사용할 수 없는 계정임을 안내한다.
- 시트 또는 설정 오류: 사용자에게 일반 오류를 표시하고 구체적인 내부 정보는 노출하지 않는다.
- 중복 이메일: 접근을 허용하지 않고 관리자 점검이 필요한 데이터 오류로 처리한다.

## 보안 및 배포 조건

- 비밀번호와 인증 토큰을 시트에 저장하지 않는다.
- 이메일 비교 시 앞뒤 공백을 제거하고 소문자로 정규화한다.
- 웹앱은 접속 사용자의 이메일을 확인할 수 있는 실행 및 접근 권한으로 배포해야 한다.
- 화면에 스프레드시트 ID, 내부 오류 스택, 다른 사용자의 정보가 노출되지 않게 한다.

## 화면 디자인

로그인 화면은 학생회 업무도구에 맞는 차분하고 간결한 단일 화면으로 구성한다. 브랜드명, Google 로그인 버튼, 처리 상태와 접근 오류를 명확히 보여준다. Figma 채널 `t5ocfhwa`에서 디자인을 읽을 수 있으면 해당 시각 기준을 우선 반영하고, 연결이 불가능하면 기존 프로젝트의 8px 모서리와 절제된 업무용 스타일을 유지한다.

## 테스트

- 등록되고 활성화된 이메일은 사용자 정보와 역할을 반환한다.
- 미등록 이메일은 접근을 거부한다.
- 비활성 이메일은 접근을 거부한다.
- 대소문자와 앞뒤 공백이 다른 이메일도 정상적으로 비교한다.
- 중복 이메일은 데이터 오류로 거부한다.
- 이메일 확인 불가와 시트 접근 실패가 안전한 오류 응답으로 변환된다.
- 로그인 화면은 모바일과 데스크톱에서 내용이 겹치거나 잘리지 않는다.
