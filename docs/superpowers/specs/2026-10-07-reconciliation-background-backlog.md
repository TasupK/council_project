# 대사 관리 백그라운드 실행 후속 과제

기록일: 2026-10-07
상태: 보류 — 현재 파일 인식 및 장부 대조 정확성 검증을 먼저 완료한다.
사용자 요청: 이번에는 기록만 하고 기능 구현은 진행하지 않는다.

## 목표

은행 거래내역을 업로드하여 장부 대조를 시작한 뒤에도 사용자가 앱 내 다른 화면에서 업무를 계속할 수 있게 한다. 화면 이동 및 새로고침 후에도 작업 상태와 결과를 복원한다.

## 합의한 사용자 흐름

1. 단일 은행 거래내역 파일 업로드 후 서버에 대조 작업을 등록한다.
2. 사용자는 다른 메뉴로 이동하여 업무를 계속한다.
3. 앱 공통 영역에 작업 진행 상태를 표시한다.
4. 완료 또는 실패 시 알림을 표시하고 대사 관리에서 결과를 다시 열 수 있게 한다.
5. 대조 결과를 검토한 사용자가 원장 연결 및 생성을 명시적으로 적용한다. 백그라운드 대조만으로 원장을 자동 변경하지 않는다.

## 구현 시 검토할 사항

- 화면 수명과 독립적인 작업 ID, 소유자, 상태, 결과 및 오류 저장.
- 대기 / 처리 중 / 완료 / 실패 상태 및 중복 실행 방지.
- GAS 실행 시간과 트리거 지연을 고려한 실행 방식, 필요 시 분할 처리 및 재시도.
- 현재 사용자의 접근 권한에 따른 작업 조회 및 원장 적용 권한 검증.
- 화면 이동 후 상태 조회 및 결과 복원, 새로고침과 실패 후 재진입.
- 대조 중 원장이 변경될 수 있으므로 적용 시 최신 원장 기준으로 재검증.
- 완료 알림과 작업 이력의 보관 기간.
- 실행 중 화면 이동 경고는 백그라운드 기능 이전의 보완책으로 검토 가능.

현재 구현은 페이지 이동 시 파일 선택 및 대조 화면 상태가 초기화된다. 이미 저장된 은행 거래와 적용된 원장 변경은 유지되며, 화면 이탈이 서버 실행 취소를 의미하지 않는다.

## 진행률 및 남은 작업 표시

추가 사용자 요구: 장부 대조가 얼마나 진행되었는지 백분율과 남은 작업을 확인할 수 있어야 한다.

- 단계 표시: 파일 업로드 → 파일 분석 → 장부 대조 → 결과 저장 → 완료.
- 전체 거래 수가 확정된 장부 대조 단계에서는 처리 완료 건수 / 전체 건수, 진행률(%), 남은 건수를 표시한다.
- 표시 예시: 전체 227건 중 150건 대조 완료 · 66% · 77건 남음. 예시는 UI 설명용이며 실제 실행 측정값이 아니다.
- 거래 건수가 아직 확정되지 않은 PDF OCR / 파일 분석 단계는 단계명 및 처리 중 표시를 사용한다. 경과 시간만으로 임의의 진행률을 만들지 않는다.
- 장부 대조가 100%여도 결과 저장 중이면 전체 작업 완료로 표시하지 않는다. 현재 단계와 거래 대조 진행률을 구분한다.
- 실패 또는 재시도 시 완료 건수, 실패 건수와 남은 작업을 구분하여 표시한다.
- 공통 영역에서는 간단한 진행 상태를 보여주고, 대사 관리의 작업 상세에서는 단계 및 건수를 보여준다.
- 남은 예상 시간은 실제 처리 속도로 신뢰할 수 있게 추정할 수 있을 때 추가로 검토한다. 초기 구현은 남은 건수를 우선한다.
- 서버가 단계 및 처리 건수를 지속적으로 기록하고 화면이 상태를 조회해야 하므로 백그라운드 작업 구조와 함께 설계한다.
